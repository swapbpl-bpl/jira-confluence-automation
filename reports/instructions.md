# How to Fill Out the Status Report

These instructions explain how to complete [template.md](template.md) for each reporting period.

## 1. Header

- **Project/Team:** Name of the project, product, or team the report covers.
- **Report Period:** Date range this report covers (e.g., `2026-09-18 – 2026-09-24`). Keep periods consistent (weekly, bi-weekly, monthly).
- **Prepared By:** Your name.
- **Date Submitted:** The date you finalize and send the report.

## 2. Summary

Write 2-3 sentences summarizing the overall state of the work. Keep it high-level — details go in the sections below.

Set **Overall Status** using one of:
- 🟢 **On Track** – progressing as planned, no significant issues.
- 🟡 **At Risk** – behind schedule, blocked, or facing risks that need attention.
- 🔴 **Off Track** – missed deadlines or major issues; escalation likely needed.

## 3. Accomplishments

List concrete, completed items from this period only. Use short, specific bullet points (e.g., "Shipped login page redesign" rather than "Worked on frontend").

## 4. In Progress

List active work items in the table:
- **Item:** Short description of the task or deliverable.
- **Owner:** Who is responsible.
- **Status:** e.g., `Not Started`, `In Progress`, `Blocked`, `In Review`.
- **Target Date:** Expected completion date.

## 5. Blockers / Risks

Only include real blockers or risks, not routine tasks. For each:
- **Issue:** What is blocking or at risk.
- **Impact:** What happens if it isn't resolved (schedule slip, scope cut, etc.).
- **Mitigation / Help Needed:** What you're doing about it, or what support you need from others.

Leave the table empty (or write "None") if there are no blockers.

## 6. Metrics

Include only metrics relevant to the project (e.g., number of commits, tickets closed, test coverage, uptime, budget spent). Remove the section if no metrics are tracked.

## 7. Next Steps

List the planned work for the upcoming period. These often become next period's "In Progress" items.

## 8. Notes

Optional. Use for context, decisions made, links to designs/PRs, or anything that doesn't fit elsewhere.

## Tips

- Keep it concise — a status report should be readable in under a minute.
- Be specific: avoid vague statements like "made progress."
- Always fill in Overall Status and Blockers honestly, even if the news is bad — that's the point of the report.
- Reuse the same file structure each period so readers know where to look.
